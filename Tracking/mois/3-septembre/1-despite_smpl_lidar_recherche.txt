CE QU'EST DESPITE

Alignement contrastif multi-modal (style CLIP), PAS une architecture JEPA :
quatre encodeurs (point cloud via PST-Transformer+tete SimCLR, IMU via LSTM
2 couches, squelette via encodeur ACTOR, texte via CLIP gele) projetes dans un
espace partage a 512 dimensions, perte InfoNCE (alignement texte + alignement
pair-a-pair entre modalites). Pas de masquage ni de prediction — different de
notre approche, donc pas un precedent architectural direct, mais deux
trouvailles empiriques directement utiles :

1. Le LINEAR PROBING SOUS-ESTIME l'apport du pre-entrainement. Citation
   directe : "linear probing shows weaker performance, indicating pretraining
   benefits accumulate through fine-tuning." Leurs gains fine-tunes sur
   HMPEAR/MSR-Action3D (+1,4 a +4,7 points) sont nettement plus nets qu'en
   probing lineaire seul. Action : mode fine-tuning ajoute a evaluation.py le
   soir meme (geler_encodeur=False, LR separe pour l'encodeur), pour retester
   l'ecart pre-entraine/aleatoire avec l'encodeur autorise a s'adapter plutot
   que juste une tete lineaire sur features figees.

2. Leur corpus d'entrainement (LIPD-Babel) atteint ~500k sequences
   d'entrainement — contre nos 864 sequences MM-Fi. Cet ecart d'echelle a lui
   seul peut expliquer une bonne partie du fosse de performance observe.


LIPD : IMPASSE POUR REPRODUIRE LA METHODE EXACTE

LIPD (dataset utilise par DeSPITE, 4DVLab/LIP sur GitHub) combine captures
LiDAR reelles ET nuages de points SYNTHETIQUES generes a partir de parametres
de pose SMPL (sur DIP-IMU, LiDARHuman26M, AIST++, sous-ensembles AMASS —
ACCAD, BMLMovi, CMU, TotalCapture). C'est exactement l'idee : simuler des
nuages LiDAR a partir de mouvements de capture de mouvement existants, bien
plus abondants et faciles a obtenir que du LiDAR reellement capture.

Verifie en detail (recherche du 3 septembre, agent dedie) : le depot GitHub ne
contient AUCUN code de simulation — seulement le chargement de nuages de
points DEJA generes (fichiers .bin/.pkl telecharges tels quels). Le papier
(arXiv:2205.15410) renvoie a "l'annexe" pour les details de simulation, mais
aucune annexe n'existe dans le PDF arXiv (v1 et v2 verifies) — probablement
seulement dans le supplement IEEE TVCG 2023, payant. Piste fermee pour
reproduire leur methode exacte sans contacter les auteurs.


AMASS : ACCESSIBLE RAPIDEMENT (PAS COMME JRDB/HMPEAR)

AMASS (amass.is.tue.mpg.de, Max Planck) unifie 15 corpus de capture de
mouvement optique en parametres SMPL+H coherents : ~346 sujets, ~11 451
sequences, ~41,5 heures, activites variees (locomotion, gestes, sport, danse,
manipulation d'objets). Formulaire d'inscription simple (email + mot de passe
+ case licence non-commerciale), AUCUNE mention d'approbation manuelle ou de
champ d'affiliation institutionnelle — rien a voir avec le processus JRDB/
HmPEAR. Complication reelle mais mineure : les modeles de corps SMPL/SMPL-X/
MANO necessitent une inscription SEPAREE (meme groupe MPI, meme type de
formulaire simple) — donc 2-3 comptes gratuits a creer plutot qu'un seul,
tous sous licence recherche non-commerciale stricte (pas de redistribution).

SIMULATION LIDAR : PAS D'OUTIL "CLE EN MAIN", MAIS UNE BRIQUE SOLIDE EXISTE

Aucun outil open-source reutilisable et generique pour "scanner un maillage
SMPL avec un LiDAR rotatif multi-faisceaux" n'a ete trouve. Quatre papiers
recents (DAPT, UniPVU-Human, LiCamPose, ReMP) ont chacun reimplemente une
version interne, non publiee, du meme pipeline (maillage SMPL + lancer de
rayons -> nuage LiDAR synthetique) — confirme que c'est un concept bien
compris mais jamais publie comme bibliotheque reutilisable.

Brique recommandee : Open3D `t.geometry.RaycastingScene` (backend Embree,
Apache-2.0, maintenu activement). Fournit le lancer de rayons contre un
maillage ; il manque seulement un generateur de grille de rayons
azimut x elevation (LiDAR rotatif) -- calcul vectoriel simple, a ecrire
soi-meme (confirme : meme PyTorch3D n'a jamais implemente cet utilitaire,
issue ouverte depuis 2020 jamais resolue). Alternative plus legere :
trimesh + ray_pyembree.

Estimation d'effort (a partir de la recherche du 3 septembre) :
  - Prototype 1 image fixe (1 pose SMPL -> 1 nuage de points) : 1-2 jours.
  - Simulateur basique sur une sequence AMASS complete (capteur mobile,
    plusieurs canaux, bruit/occlusion simples) : ~1 semaine.
  - Fidelite a un capteur reel precis (distorsion de mouvement type
    rolling-shutter, intensite, bruit valide empiriquement) : echelle
    "contribution de papier de recherche", pas un projet d'une semaine.
